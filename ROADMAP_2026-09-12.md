# Roadmap 2026-09-12 — von Batch A+B zu den Use-Case-Schienen

Nachfolgestufe von [AUDIT_2026-09-12_TODO.md](AUDIT_2026-09-12_TODO.md) (Findings verifiziert,
Batch A+B implementiert, uncommittet). Diese Roadmap ordnet die nächsten Wochen in sieben
Makro-Schritte mit harten Gates.

**Arbeitsprinzipien („warum genau diese Reihenfolge"):**

1. **Bestand vor Ausbau** — nichts Neues bauen, solange fertige Arbeit uncommittet liegt
   (unkomittierte 386-grüne Tests sind unversichertes Risiko).
2. **Entscheiden vor Bauen** — jedes Design-Tor (M2) wird geschlossen, bevor die betroffene
   Schiene (M3+) Code bekommt; keine Baustellen ohne Entscheidungsbasis.
3. **Evidence-driven** — jeder Schritt endet mit einem messbaren Artefakt (grüne CI, JSON mit
   `measured:true`, committed Rezept); keine Behauptung ohne Beleg (IP-Posture).
4. **Single-WIP + Check-in** — ein Makro-Schritt aktiv, danach Kurz-Check-in mit Ergebnis
   und Go/No-Go für den nächsten; trunk-based, kleine konventionelle Commits.

Legende: Aufwand S = Stunden, M = 1–2 Tage, L = >2 Tage. Jeder Schritt hat ein **Gate**
(DoD) — erst bei Gate-pass geht's weiter.
